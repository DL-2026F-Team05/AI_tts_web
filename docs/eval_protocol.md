# 평가 방법

```
python -m evaluation.run_eval --root /content/drive/MyDrive/DL-Team05/data --ocr easyocr --out outputs/eval_easyocr
```

결과: `summary.md`(보고서용 표), `report.json`(전체 숫자), `per_image.csv`(사진별 결과, 오류 분석용)

## 지표

### OCR
- **CER**: 글자 편집 거리 / 정답 글자 수. 한국어는 음절 단위(자모 아님), 공백은 빼고 센다. 사진 전체 글자를 읽는 순서대로 이어 붙여 비교하고, 여러 사진을 합쳐서 계산한다.
- **WER**: 띄어쓰기 단위(어절) 편집 거리 / 정답 어절 수
- **검출 P/R/F1**: 글자 박스를 IoU 0.5 이상으로 1:1 짝지어서 계산
- **영역 혼동행렬**: 짝지어진 박스의 정답 영역 vs 예측 영역 (영역 검출기를 붙였을 때 의미가 있다)

### 소비기한
날짜가 보이는 사진(박스 정답의 소비기한 칸에 숫자가 있거나, 정답표의 `expiry_face`와 사진 면이 같은 경우)만 센다.
- **날짜 정확도**: 예측 날짜 = 정답 날짜
- **보류율**: `unknown`/`elsewhere`로 답한 비율
- **틀린 날짜를 말한 비율**: 보류하지 않고 틀린 날짜를 말한 비율 (가장 위험한 실패)
- **지난 제품을 놓친 비율**: 정답이 지났는데 `ok`/`soon`이라고 한 비율 = 소비기한 위험 놓침률

날짜가 안 보이는 사진에서는 **날짜를 지어낸 비율**(아무 날짜나 말한 비율)을 센다.

**coverage-risk 표**: 신뢰도 기준값을 0~1로 바꿔 가며 (답한 비율, 답한 것 중 틀린 비율)을 계산한다. 이 그래프로 `Config.expiry_min_conf`를 정한다.

### 알레르기
알레르기가 보이는 사진(박스 정답에 알레르기 칸이 있거나 `back` 면)만 센다.
- 19종 성분별 tp/fp/fn → **micro P/R/F1**, **macro F1**(한 번이라도 나온 성분 평균)
- **놓친 비율** = fn / (tp + fn) = 알레르기 위험 놓침률. 사용자가 그 성분 알레르기가 있었다면 경고를 못 받았을 비율이다.

### 제품명
- 제품명 CER 평균 (`front`, `back` 사진)

### 촬영 조건별
파일 이름의 조건(`normal`, `lowlight`, `glare`, `blur`, `crumple`, `curve`, `angle`)별로 CER, 날짜 정확도, 보류율. 전처리 전후(배창현), 모델별(이도현) 비교에 같은 표를 쓴다.

### 처리 시간
단계별 중앙값. 웹 데모에서는 사진을 올린 순간부터 첫 음성이 나올 때까지를 따로 기록한다 (`logs/events.jsonl`의 `first_audio`).

## 설명 가능성 (Grad-CAM)
영역 검출기(YOLO)에 EigenCAM을 붙여 소비기한·성분표 영역에 주목하는지 본다 (`pip install grad-cam`, pytorch-grad-cam). 잘 된 사례와 틀린 사례를 같이 보고서에 넣는다.

## 사용자 테스트
- 참가자: 시각장애인 섭외가 어려우면 안대를 쓴 참가자로 하고, 그 한계를 보고서에 적는다
- 과제: 제품 5개를 받아 (1) 소비기한이 지났는지 (2) 등록한 알레르기 성분이 있는지 앱으로 알아내기
- 측정: 과제 성공률, 첫 음성까지 시간, 다시 듣기·더 듣기 횟수 (데모가 자동 기록), 걸린 시간
- 설문 (5점): 안내가 알아듣기 쉬웠다 / 중요한 정보가 먼저 나왔다 / 말 속도가 적당했다 / 다시 쓰고 싶다
- 참가 동의를 받고, 이름 대신 번호로 기록한다
