# 실제 OCR로 확인한 문제와 대응

2026-11-09, 코랩(CPU)에서 EasyOCR(ko, en)로 `data/samples` 합성 샘플 6장을 읽었다. 가짜 OCR(정답을 그대로 돌려줌)에서는 다 맞던 흐름이 실제 OCR에서는 아래처럼 깨졌다.

- 실제 출력 원본: `tests/fixtures/easyocr_samples.json`
- 회귀 테스트: `tests/test_real_ocr.py` (고친 뒤 결과가 다시 깨지면 테스트가 실패한다)

## 발견한 문제

| # | 문제 | EasyOCR가 실제로 읽은 글자 | 영향 | 대응 | 남은 일 |
|---|---|---|---|---|---|
| 1 | 조사 오인식 | "땅콩, 새우**틀** 사용한 제품과", "호두**름**" | 혼입 경고(땅콩)가 빠짐. **위험 놓침** | 혼입 문구에서 조사를 목록 쪽에 두고, 이름 뒤 한 글자를 떼어 맞춰 봄 | 표준 문구가 아닌 혼입 표현 (이서영) |
| 2 | 한 줄이 박스 여러 개로 쪼개짐 | "영양정보: 총 내용량" / "120g," / "165kcal 나트룹" / "7Omg" | 문장 규칙이 줄 일부만 봄 | 같은 줄 박스를 이어 붙여서 봄 (`ocr.group_lines`) | |
| 3 | 숫자 옆 O·l 오인식 | "6Og", "19OmL", "9oOmL", "32Okcal" | 단위 읽기가 깨짐 ("육Og") | OCR 후처리로 0·1로 고침 (`ocr.clean_ocr_text`) | |
| 4 | 제품명 오인식, 신뢰도 낮음 | "바싹 고소집"(0.41), "듣튼 두유"(0.43). 정답은 바삭 고소칩, 든든 두유 | 기준(0.5) 미달로 제품명을 아예 안 읽음 | 0.3 이상이면 "제품은 ○○로 보여요"처럼 단정하지 않고 읽음 | 인식기 파인튜닝, 제품명 영역 검출 (이도현) |
| 5 | 점 글씨 날짜를 전혀 못 읽음 | 신뢰도 0.00~0.02의 엉뚱한 글자 | 날짜 면을 찍어도 소비기한을 못 알려 줌 | 첫 OCR이 비면 점을 이어 붙여(모폴로지 닫힘) 다시 읽음. 커널 5·9는 실패, 13에서 "2026.12.24"(0.73) | 실제 뚜껑·바닥 사진으로 커널 크기와 조명 조건 확인 (배창현) |
| 6 | 기호·글자 오인식 | "0~10℃" → "O~109C", "100%" → "1009", "나트륨" → "나트룹/나트톱" | '더 듣기' 음성이 이상하게 읽힘 | 아직 없음 | 후처리 사전 또는 파인튜닝 (이도현, 이서영) |
| 7 | 속도 | 한 장에 15~22초 (CPU) | 시연에 쓰기 어려움 | 코랩 런타임을 T4 GPU로 바꿔서 측정 예정 | |

## 안내 문장 길이 (edge-tts, 기본 속도)
| | 고치기 전 | 고친 뒤 |
|---|---|---|
| S001 요약 | 18초 | 13.3초 |
| S001 더 듣기 | | 35.4초 |

겹치는 설명("같은 시설에서 함께 만들어요")은 '더 듣기'로 옮기고, 30일 넘게 남은 날짜는 남은 날 수를 빼고, "2027년" 대신 "내년"이라고 해서 줄였다. 더 줄일지는 사용자 테스트에서 정한다 (말하기 속도는 화면에서 바꿀 수 있다).

## 보고서에 쓸 만한 점
- 가짜 OCR로 흐름만 맞추면 안 보이는 위험 놓침(1번)이, 깨끗한 합성 사진에서도 실제 OCR로 바로 드러났다. 실제 촬영 사진에서는 더 많이 나올 것이라, 위험 놓침률을 따로 재는 이유가 된다.
- 점 글씨 날짜(5번)는 모델을 바꾸지 않고 전처리만으로 읽히게 만든 사례다.
